# Sufler

Суфлёр для iPhone, который показывается **поверх других приложений** и прокручивает текст
**за вашей речью** — без ручного скролла и без режима постоянной скорости.

React Native (Expo SDK 57, New Architecture) + Zustand + Reanimated 4, с нативным Swift-модулем,
который делает две вещи, недоступные из JS: рисует кадры суфлёра в окно Picture in Picture и
ведёт позицию по тексту через Apple Speech.

---

## Что важно понимать до того, как вы это соберёте

Два ограничения iOS определили всю архитектуру. Оба непреодолимы, и оба лучше узнать сейчас.

### 1. Настоящего оверлея на iOS нет

Аналога Android `SYSTEM_ALERT_WINDOW` не существует: обычное приложение не может рисовать поверх
чужих окон. Единственный легальный способ — **Picture in Picture с кастомным
`AVSampleBufferDisplayLayer`**: текст рендерится в `CMSampleBuffer` и отдаётся системе как
видеопоток. Так работают и другие суфлёры в App Store.

Отсюда следует `UIBackgroundModes: ["audio"]` в `Info.plist` — это требование самого PiP, а не
наша прихоть. Про риски ревью см. ниже.

### 2. Микрофон на iPhone эксклюзивен

Пока другое приложение пишет звук, Sufler не слышит вас. Конкретно:

| Сценарий | Оверлей | Следование за речью |
|---|---|---|
| Заметки, браузер, Telegram, слайды | ✅ | ✅ |
| Камера в режиме превью (без записи) | ✅ | ✅ |
| **Камера пишет видео** | ✅ | ❌ прокрутка останавливается |
| **Звонок в Zoom / Meet / FaceTime** | ✅ | ❌ прокрутка останавливается |

Обходного пути нет — `.mixWithOthers` разрешает совместное *воспроизведение*, но не совместный
*ввод*. Приложение это не скрывает: при перехвате микрофона в кадр PiP прямо рисуется
«⏸ Микрофон занят другим приложением», а курсор замирает там, где вы остановились, и продолжает с
того же места, как только микрофон освободится.

Реалистичный сценарий — Sufler единственный пользуется микрофоном, а поверх него у вас заметки,
браузер или чужая презентация.

## Возможности

- **Загрузка текста**: набрать/вставить вручную, импорт `.txt` / `.md` из Файлов и iCloud,
  «Поделиться» текстом или файлом из любого приложения через нативный Share Extension.
- **Оверлей**: окно Picture in Picture поверх других приложений. Открывается кнопкой или само,
  когда вы уходите из Sufler.
- **Старт / Стоп**: и в приложении, и кнопкой play/pause в самом окне PiP — единственный доступный
  контрол, когда вы уже в другом приложении.
- **Следование за речью**: `SFSpeechRecognizer` + нечёткое выравнивание распознанного с текстом.
- Зеркальное отражение для съёмки через светоделительное стекло, размер шрифта, межстрочный
  интервал, настройки алгоритма и отладочная полоска.

## Архитектура

### Три уровня состояния

Аллайнер обновляет позицию 5–20 раз в секунду. Куда попадает это число — главное архитектурное
решение в проекте.

| Уровень | Что хранит | Частота |
|---|---|---|
| Нативка (`SuflerSession`) | авторитетный курсор, токены, кадр PiP, аудиосессия | 5–20 Гц |
| Reanimated shared values | `tokenIndex`, `lineIndex`, `indexInLine` | 12 Гц вход, 120 Гц выход |
| Zustand | скрипты, статус, настройки, права, ошибки | единицы раз за сессию |

**Курсор никогда не попадает в Zustand или React state.** `set()` на 12 Гц перерисовывает всех
подписчиков и превращает суфлёр в слайд-шоу. Запись в shared value с JS-потока не вызывает
ре-рендера вообще, а сама прокрутка идёт на UI-потоке.

### Нативный модуль

Один локальный Expo Module (`modules/sufler-core`), один под, три `ModuleDefinition` поверх общего
процессного синглтона. Один под потому, что аллайнер пушит курсор в PiP-рендерер несколько раз в
секунду: гонять это через JS-мост означало бы round-trip native → JS → native на каждое
распознанное слово, на JS-потоке, пока React рендерит.

```
modules/sufler-core/ios/
  Session/   SuflerSession, AudioSessionManager, ScriptModel, PositionBus
  PiP/       SuflerPiPModule, PiPController, PiPSourceView,
             SampleBufferPump, PixelBufferPool, TeleprompterFrameRenderer
  Speech/    SuflerSpeechModule, SpeechBackend, SFSpeechBackend,
             MicEngine, Aligner, TextNormalizer
  Inbox/     SuflerInboxModule
```

### Алгоритм следования

Локальное выравнивание Нидлмана–Вунша хвоста распознанного против окна скрипта — не скользящее
скалярное произведение. Разница принципиальная: стоит диктору пропустить слово или распознавателю
вставить лишнее, как позиционное сравнение уезжает на единицу и оценка обваливается. Выравнивание
с гэпами поглощает ровно эти два случая, а на них приходится большая часть реальных сбоев.

```
hyp    = последние 7 распознанных слов минус филлеры («э», «ну», «типа»…)
WINDOW = script[cursor-8 … cursor+60]

sim(a,b) = 1.00  совпали нормальные формы (числа матчатся и цифрой, и прописью)
           1 - lev/max(len), если ≥ 0.75
           0.60  общий префикс ≥ 4 символов   // «говорил» / «говорит»

GAP_SCRIPT = 0.25  < GAP_HYP = 0.55
   пропуск слова диктором нормален; галлюцинация распознавателя — сигнал слабее

score[j] = D[m][j]/m − дрейф   (вперёд 0.004/токен, назад 0.030/токен)

HOLD, если best < 0.55                       — шум
HOLD, если best − runnerUp < 0.10            — фраза повторяется, ждём уточнения
назад — только при best ≥ 0.80 и ≤ 8 токенов
прыжок > 25 токенов — только при best > 0.80, иначе ползём +3
```

Курсор принадлежит аллайнеру, а не распознавателю. Поэтому обязательная ротация запроса
`SFSpeechRecognizer` (лимит ~1 мин в облачном режиме, накопление транскрипта в on-device) ничего не
теряет: распознаватель stateless, он лишь сообщает «вот что я услышал только что».

Тишина **не** двигает текст. Через 8 секунд молчания окно поиска расширяется до ±200 токенов, чтобы
поймать докладчика, ушедшего вперёд по своим заметкам.

### Рендерер PiP

Рисуем прямо в base address пиксель-буфера через `CGContext` — без промежуточных `UIImage`/
`CGImage`. Драйвер — `CADisplayLink` с dirty-флагом: кадр производится только при смене курсора или
текста, плюс heartbeat 1 Гц; после 3 секунд покоя display link гасится совсем. В среднем по
выступлению это 4–6 fps, а во время пауз — ноль.

Три вещи, из-за которых окно PiP молча становится чёрным, и все три здесь учтены:
`kCVPixelBufferIOSurfacePropertiesKey` в атрибутах пула, PTS из
`CMClockGetTime(CMClockGetHostTimeClock())`, и attachment `DisplayImmediately` вместо control
timebase.

Карточка предпросмотра на экране суфлёра — не декорация: авто-PiP не включится, если слой скрыт,
прозрачен, нулевого размера или лежит в `<Modal>` (другое окно — не key window). Показывать
пользователю ровно те кадры, что уйдут в оверлей, честнее спрятанной вьюхи 1×1 — и это единственный
способ увидеть рендерер на симуляторе, где самого PiP нет.

### Аудиосессия

Одна сессия на всё приложение, настраивается один раз, активация по счётчику ссылок:

```swift
.playAndRecord, mode .default,
options: [.mixWithOthers, .defaultToSpeaker, .allowBluetoothHFP, .allowBluetoothA2DP]
```

`.mixWithOthers` обязателен — суфлёр не имеет права глушить чужую музыку. Категория не меняется,
пока PiP активен: смена категории на живом `AVAudioEngine` инвалидирует формат тапа.

Постоянного silent-audio keep-alive здесь **нет**: наш фоновой звук — сам микрофонный захват.

## Сборка

Нужны macOS, Xcode 17+ (iOS 17 SDK и выше), Node 20+, CocoaPods.

```bash
npm install
npx expo prebuild -p ios --clean
cd ios && LANG=en_US.UTF-8 pod install && cd ..

npx expo run:ios              # симулятор
npx expo run:ios --device     # реальный iPhone — нужен для PiP
```

`ios/` и `android/` в репозиторий не коммитятся: они целиком генерируются `prebuild` из
`app.config.ts` и config-плагина. Править `ios/` руками нельзя — `prebuild --clean` всё сотрёт.

Подпись: один раз откройте `ios/Sufler.xcworkspace` и выставьте команду разработки на **обоих**
таргетах (`Sufler` и `SuflerShare`). Плагин делает всё остальное, кроме `DEVELOPMENT_TEAM`.

App Group `group.com.igorao.sufler` должен быть включён для обоих bundle id в Apple Developer
Portal, иначе `containerURL(forSecurityApplicationGroupIdentifier:)` вернёт `nil` и шеры будут
молча пропадать. Приложение проверяет это и пишет в лог.

## Проверка

```bash
npm run lint                  # tsc --noEmit
./scripts/check-aligner.sh    # алгоритм следования на смоделированной расшифровке

# перед каждой загрузкой в App Store Connect, по собранному архиву:
./scripts/check-purpose-strings.sh <path>.xcarchive
```

`check-purpose-strings.sh` обходит все Mach-O внутри бандла — приложение, расширение и каждый
фреймворк — и сверяет privacy-чувствительные API, на которые они *ссылаются*, с ключами
`NS*UsageDescription` в `Info.plist`. Валидация Apple смотрит именно на ссылки, а не на вызовы,
поэтому хватает одной зависимости несколькими уровнями ниже: `expo-file-system` линкует `Photos`,
`react-native-reanimated` — `CoreMotion`, хотя приложение не трогает ни то, ни другое. Узнавать об
этом из письма-отказа стоит одной загрузки и одного номера билда каждый раз.

`check-aligner.sh` компилирует `Aligner`, `ScriptModel` и `TextNormalizer` отдельно (они зависят
только от Foundation) и прогоняет их против набора случаев: дословное чтение, слова-филлеры, число
цифрой против числа прописью, пропущенное слово, другое словоизменение, прыжок через абзац и
посторонняя речь, которая двигать курсор не должна. Это единственная часть приложения, чью
правильность не видно на скриншоте.

| Что проверяем | Симулятор | Устройство |
|---|---|---|
| UI, навигация, стор, прокрутка Reanimated | ✅ | ✅ |
| Импорт `.txt`/`.md`, Share Extension, App Group | ✅ | ✅ |
| Рендер кадров суфлёра (через карточку предпросмотра) | ✅ | ✅ |
| `SFSpeechRecognizer`, облачный режим | ✅ (микрофон Mac) | ✅ |
| `SFSpeechRecognizer` on-device | ⚠️ обычно недоступен | ✅ |
| PiP поверх приложений, play/pause, смена размера окна | ❌ `isPictureInPictureSupported()` == false | ✅ |
| Работа в фоне, прерывания аудио, перехват микрофона | ❌ | ✅ |

**Что проверено, а что нет.** Всё из строк с ✅ в колонке «Симулятор» прогонялось вручную, включая
сквозной путь: приход текста через App Group → библиотека → суфлёр → Старт → запуск распознавания и
переход в «пауза» по тишине. Строки с ❌ физически непроверяемы без устройства.

## Риски

**Ревью App Store — `UIBackgroundModes: ["audio"]`.** Гайдлайн 2.5.4 требует реально отдавать звук
в фоне; мы отдаём микрофонный захват и PiP-видео. Это защитимо — PiP по документации Apple требует
этот режим — но остаётся суждением ревьюера. Что помогает: не шипить постоянный silent-loop, дать
PiP на скриншотах заглавной фичей, объяснить связку PiP + `SFSpeechRecognizer` в review notes и
приложить видео (у ревьюера PiP на симуляторе тоже не заведётся).

**On-device распознавание русского.** `supportsOnDeviceRecognition` зависит от устройства и локали.
Фолбэк на облачный режим с явным уведомлением; там появляется лимит ~1 мин на запрос (снимается
ротацией), зависимость от сети и недокументированные суточные лимиты.

**Батарея.** Непрерывный захват микрофона плюс распознавание плюс композитинг PiP — примерно
15–25 % в час. Смягчено dirty-флагом рендера, засыпанием display link и `CAFrameRateRange` c
минимумом 8 fps.

**Хрупкость config-плагина.** `withXcodeProject` правит `pbxproj` — самое ломкое место в
репозитории. Если после `prebuild` в проекте нет таргета `SuflerShare` или фазы копирования в
PlugIns, смотреть надо в `plugins/withSuflerShareExtension.ts`.

**Android — вне скоупа v1.** JS-слой платформенно-нейтрален, нативные модули на Android
резолвятся в `null`, приложение запускается.
